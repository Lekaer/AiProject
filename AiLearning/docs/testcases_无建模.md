# 测试用例

## 1. 补缴单恢复——状态为“已取消”可恢复为“待支付”
- **类型**: 边界值分析
- **前置条件**: 1. 存在一笔品质保证金补缴收款订单，订单状态为“已取消”；
2. 该补缴单对应的扣款订单已完成或已取消；
3. 该补缴单无任何实收记录（实收金额=0）。
- **步骤**: ["1. 登录有商户资金权限的账号，进入河图小工具“恢复补缴单”页面；","2. 输入该补缴单的订单ID，点击“查询”；","3. 查看查询结果中订单状态显示为“已取消”；","4. 点击“恢复订单”按钮；","5. 在弹出的确认框中点击“确定”。"]
- **预期结果**: 1. 点击查询后正确展示该订单信息，且“恢复订单”按钮可用；
  2. 点击“恢复订单”后弹窗提示：“订单状态将恢复为待支付，是否要恢复该订单状态？”；
  3. 点击“确定”后，页面提示操作成功，订单状态变更为“待支付”；
  4. 数据库中订单状态同步更新为待支付，且相关的补缴逻辑可继续流转。

## 2. 补缴单恢复——状态为“待支付”不允许恢复
- **类型**: 边界值分析
- **前置条件**: 存在一笔品质保证金补缴收款订单，订单状态为“待支付”，无实收记录。

- **预期结果**: 1. “恢复订单”按钮置灰不可点击，或点击后弹窗提示“当前订单状态不允许恢复”；
  2. 订单状态保持“待支付”不变。

## 61. 多费用项混合取消与权限校验组合
- **类型**: 组合场景
- **前置条件**: 1. 已存在以下订单：
   - 品质保证金收款订单C（二手签约场景，状态待支付，实收0元）；
   - 意向金收款订单D（非二手签约场景，状态待支付，实收0元）；
   - 品牌保证金扣款订单E（无实收，状态待支付）；

3. 订单C、D、E均未关联在途账单；

  5. 跨费用项操作中权限校验正常，无越权提示，操作日志中准确记录各订单操作人与结果。
