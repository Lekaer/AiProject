# 异常路径

## 何时使用

- 任务调用外部系统/第三方接口（同步类任务重点）
- 任务接受用户输入或文件上传
- 存在并发操作、重复提交风险

## 测试点生成规则

识别需求文档中依赖的外部系统、用户输入点、并发操作场景。对每个风险点生成以下测试点：
- 输入异常：null值、格式错误、类型不匹配、超长内容、特殊字符注入
- 依赖异常：下游服务超时、返回异常、不可达
- 并发异常：同一资源同时操作、重复提交
- 资源异常：存储满、内存溢出、连接池耗尽

结合业务知识：历史缺陷中提到的异常场景和故障记录应优先覆盖。

## 用例展开规则

对每个异常测试点，展开为完整用例：
- 前置条件描述正常环境配置和触发异常的特定条件
- 测试步骤中先建立正常状态，再触发异常
- 预期结果明确：系统返回具体错误码、不影响其他业务、有合理日志记录

## 反例（不要这样做）

- 只测"系统报错"不写具体错误码和隔离性——异常用例的预期必须可判定
- 把正常值边界当异常测——越界数值走 boundary_value
