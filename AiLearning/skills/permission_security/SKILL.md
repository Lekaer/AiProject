# 权限安全

## 何时使用

- 任务涉及多种用户角色或审批权限
- 任务访问/展示敏感数据（证件、金额、个人信息）
- 接口需要认证或存在多租户数据隔离要求

## 测试点生成规则

识别需求文档中涉及的用户角色、权限控制点、敏感数据。对每个权限边界生成以下测试点：
- 未认证访问：不携带token/携带无效token访问
- 角色越权：低权限角色尝试高权限操作
- 跨租户隔离：租户A尝试访问租户B的数据
- token安全：过期token、被篡改token、不同用户token
- 敏感数据：响应中是否泄露密码/密钥、日志中是否脱敏

结合业务知识：业务规则中定义的权限模型和审批流程是设计权限用例的基础。

## 用例展开规则

对每个权限测试点，展开为完整用例：
- 前置条件中明确当前用户角色、权限状态、所属租户
- 测试步骤中详细写出请求头、参数和认证凭据
- 预期结果明确：返回403/401、数据隔离正常、无敏感信息泄露

## 反例（不要这样做）

- 只测"无权限不可访问"一句带过——必须明确角色、凭据、具体状态码
- 把格式错误的 token 当输入异常——那是 exception_path；权限语义错误才是本技能
