# 状态机覆盖

## 何时使用

- 任务中的实体有明确生命周期状态（订单、工单、申请单、审核流）
- 规则中出现"驳回后重新提交""暂存后再编辑"等状态跳转描述

## 测试点生成规则

识别需求文档中具有状态流转的实体（如订单、工单、申请单）。梳理完整的状态机图后，生成以下测试点：
- 每个合法状态转换路径（正向流程）
- 每个非法状态转换（如从终态退回中间态）
- 重复执行同一状态变更（幂等性）
- 并发状态变更（两个请求同时改状态）
- 状态变更后的回滚/撤销

结合业务知识：业务规则中定义的状态流转规则是设计状态机用例的唯一依据。

## 用例展开规则

对每个状态机测试点，展开为完整用例：
- 前置条件明确当前状态和触发操作
- 测试步骤中先设置初始状态，再执行状态变更操作
- 预期结果明确：状态变更成功/被拒绝、数据一致、幂等操作无副作用

## 反例（不要这样做）

- 只覆盖正向流转——非法转换和幂等才是状态机测试的价值所在
- 把"更新后数据对不对"当事务问题——那是 data_consistency；本技能管"状态能不能转"
