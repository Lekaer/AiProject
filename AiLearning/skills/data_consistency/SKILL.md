# 数据一致性

## 何时使用

- 同步类任务：从外部系统拉取/推送数据
- 任务涉及多表写入、缓存更新、级联操作
- 规则中出现"以 X 为准""刷新缓存""重复提交"等字样

## 测试点生成规则

识别需求文档中涉及数据库操作、缓存使用、多表关联的场景。对每个数据操作点生成以下测试点：
- 事务回滚：操作链中间失败，前置操作是否正确回滚
- 幂等性：相同请求重复发送（如用户双击提交）
- 缓存一致性：数据更新后缓存是否同步失效/更新
- 读写一致性：写后立即查，读到的是否为最新数据
- 级联操作：主表删除后关联表是否正确处理

结合业务知识：业务规则中的数据校验逻辑和关联关系是数据一致性测试的基础。

## 用例展开规则

对每个数据一致性测试点，展开为完整用例：
- 前置条件中准备好初始数据和关联数据
- 测试步骤中模拟失败点（如断网、超时）并观察数据状态
- 预期结果明确：数据要么全部成功要么全部回滚，无中间状态

## 反例（不要这样做）

- 预期只写"数据正确"——必须指明哪张表/哪个缓存/什么值，否则无法判定
- 把下游超时当一致性测——超时本身是 exception_path；超时后的数据状态才是本技能
