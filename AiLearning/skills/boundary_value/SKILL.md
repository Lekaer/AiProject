# 边界值分析

## 何时使用

- 任务规则中出现显式数值约束：「0%-100%」「1-50000 元」「限领 1-10 张」「不超过 200 字」
- 业务规则提到限额、阈值、周期、有效期

## 测试点生成规则

识别需求文档和业务规则中所有涉及数值、日期、字符串、集合的输入和参数。对每个参数生成以下测试点：
- 最小边界值（如最小值、最早日期、空字符串、空集合）
- 最大边界值（如最大值、最晚日期、最大长度、最大数量）
- 边界+1（超出上限）和边界-1（低于下限）
- 零值、负值（如适用）

结合业务知识：业务规则中提到的限额、阈值、周期等应作为边界值测试的重点。

## 用例展开规则

对每个边界测试点，展开为完整用例：
- 前置条件必须明确设定边界场景（如当前值为阈值-1）
- 测试步骤中写明具体输入值和验证方式
- 预期结果须明确：接受并正确处理 / 拒绝并给出具体错误码 / 系统稳定不崩溃

## 反例（不要这样做）

- 只测 min/max 不测 min-1/max+1——漏掉无效侧等于没测边界
- 把并发、越权、状态机用例混进来——那是其他技能的职责
